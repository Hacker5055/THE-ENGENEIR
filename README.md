## ما هذا المستودع؟

نسخة عاملة من منصة «المهندس»، مبنية كمنتج حقيقي لا كنموذج ثابت: كل زر ونموذج وفلتر يعمل على بيانات فعلية محفوظة على الخادم، وكل عملية حساسة تُنتج أثراً في سجل التدقيق. لا توجد واجهة تدّعي وظيفة غير موجودة.

| الطبقة | التقنية |
| --- | --- |
| الواجهة | Next.js 16 (App Router · Turbopack) · React 19 · TypeScript · Tailwind 4 |
| البيانات | متجر خادم حتمي (96 طالباً، 11 عضواً، 4 مقررات، اختبار مباشر، 20+ تذكرة) + DDL جاهز في `db/schema.sql` |
| المصادقة | جلسات HTTP-only (8 ساعات) + تحقق بخطوتين (6 أرقام، 5 دقائق، 5 محاولات) — تُحفظ الجلسات في `.data/auth-state.json` فلا يُخرجك إعادة التشغيل |
| الاختبارات | مؤقّت مرجعي على الخادم، حفظ فوري بمراجعة (revision)، تصحيح آلي للموضوعي، قرار حوادث بشري |
| الحضور | رمز QR متغيّر كل 20 ثانية، جهاز مسجّل، نطاق جغرافي 120 م، تجاوز معلم مسجّل |
| البحث | ⌘K في كل بوابة يبحث في الطلاب/المعلمين/المقررات/الاختبارات/الشكاوى حسب صلاحية الدور، وصفحة بحث داخل تطبيق الطالب |
| السجلات | إضافة طالب أو عضو هيئة تدريس من الواجهة أو عبر `POST /api/v1/students|teachers` — يُنشأ حساب دخول فعلي ويُكتب في التدقيق |
| التحقق | رمز QR على الهوية الرقمية يفتح صفحة تحقق عامة تعرض الحالة فقط (بلا درجات أو بيانات تواصل) |

## التشغيل

المستودع كامل يُثبَّت ويُشغَّل **من الجذر** — لا حاجة للدخول إلى `web/`:

```bash
npm install          # يثبّت مساحة العمل web/ (npm workspaces)
npm run dev          # http://localhost:3000  (يستمع على 0.0.0.0 للعرض داخل حاويات/معاينات)
npm run build        # بناء الإنتاج
npm run start        # تشغيل الإنتاج
npm run typecheck    # فحص الأنواع
npm run smoke        # اختبار E2E شامل (27 فحصاً) — يحتاج خادماً يعمل على :3000
```

المتطلبات: **Node ≥ 20.9** و npm ≥ 10. لا توجد أي اعتمادية أصلية (native) مطلوبة للتشغيل؛ أدوات توليد شعارات العلامة التجارية وحدها تحتاج حزمتين اختياريتين:

```bash
npm i -D @resvg/resvg-js fontkit     # فقط لإعادة توليد brand/*.png
```

### التشغيل على منصات الاستضافة الآلية (Google AI Studio / StackBlitz / CodeSandbox)

هذا التطبيق **Next.js بخادم Node** (Server Actions، Middleware، تصيير على الخادم) وليس تطبيق Vite ثابتاً. لذلك:

- ملف `package.json` موجود الآن في **جذر المستودع** مع `web` كمساحة عمل، وملف قفل واحد `package-lock.json` في الجذر — هذا ما كان يمنع التثبيت سابقاً («Dependency installation failed») عند استيراد المستودع كاملاً، لأن الجذر لم يكن يحمل بياناً.
- أي منصة تشغّل أمر `npm run dev` على Node ستعمل مباشرة؛ الخادم يستمع على `0.0.0.0:3000`.
- منصة تقبل **Vite فقط** لن تشغّل هذا المشروع كما هو — استخدم معاينة Node (هذه البيئة) أو Vercel/أي مستضيف Node.

## الحسابات التجريبية

| الدور | البريد | كلمة المرور | يفتح |
| --- | --- | --- | --- |
| طالب | `student@almohandes.edu` | `Student@123` | تطبيق الطالب (جوال) |
| معلم | `teacher@almohandes.edu` | `Teacher@123` | لوحة المعلم |
| مراقب اختبارات | `supervisor@almohandes.edu` | `Super@123` | مركز المراقبة |
| مدير مؤسسة | `admin@almohandes.edu` | `Admin@123` | لوحة الإدارة |
| مدير منصة | `root@almohandes.edu` | `Root@123` | مركز التحكم |

> **إن ظهرت رسالة «انتهت صلاحية التحقق»:** افتح المعاينة في **تبويب مستقل** (لا داخل إطار)، ثم حدّث الصفحة تحديثاً كاملاً (Ctrl/Cmd+Shift+R) وسجّل الدخول. بعض المتصفحات تحجب كوكيز الطرف الثالث داخل الإطارات، فتضيع الجلسة بعد التحقق — وفي هذه الحالة تعرض المنصة صفحة `/welcome` تشرح السبب بدل إعادة توجيه صامتة.

مسارات مساعدة للتجربة (تُرجع 404 إلا عند `ALLOW_DEV_SESSION=1` أو في التطوير): `POST /api/dev/session` (جلسة ببريد)، `POST /api/dev/challenge` (رمز), `POST /api/dev/reset` (`{"examId","studentId"}` لتصفير محاولة، أو `{"reseed":true}` لإعادة كل البيانات التجريبية).

رمز التحقق يُعرض داخل شاشة التحقق في هذه النسخة التجريبية (لا يوجد بريد فعلي)، ويُطلب فعلياً في الإنتاج.

كل طالب ومعلم في البيانات التجريبية له حساب عامل أيضاً — بريد الطالب هو رقمه الجامعي بحروف صغيرة (`am20231002@almohandes.edu`) وكلمة المرور `Student@123`، وبريد المعلم مأخوذ من اسمه مع `Teacher@123`. بذلك يمكن فتح أي سجل في المنصة بشخصه الحقيقي، لا بحساب واحد فقط.

```
├─ docs/                 حزمة التسليم بصيغة Markdown
├─ brand/                الشعار والنسخ والكلمة (SVG/PNG)
└─ scripts/              توليد الشعار، الكلمات، والمستندات
```

## الاختبار الآمن: ما نضمنه وما لا نضمنه

| القدرة | جهاز مُدار (MDM) | جهاز شخصي |
| --- | --- | --- |
| قفل التطبيقات الأخرى | نعم | لا |
| منع لقطات الشاشة | نعم (Android) / جزئياً (iOS) | لا |
| كشف تبديل التطبيق | نعم | نعم — حدث موثّق |
| كشف الجذر/كسر الحماية | نعم | نعم — يُسجَّل |
| منع تسجيل الشاشة | نعم | لا |

لا ندّعي حجزاً كاملاً للجهاز على الأجهزة الشخصية. المؤقّت من الخادم، الإجابات تُحفظ فوراً، وكل حادثة تُصنَّف وتُعرض على مراقب بشري — ولا تُلغى أي محاولة آلياً.
