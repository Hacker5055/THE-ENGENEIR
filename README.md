## ما هذا المستودع؟

نسخة عاملة من منصة «المهندس»، مبنية كمنتج حقيقي لا كنموذج ثابت: كل زر ونموذج وفلتر يعمل على بيانات فعلية محفوظة على الخادم، وكل عملية حساسة تُنتج أثراً في سجل التدقيق. لا توجد واجهة تدّعي وظيفة غير موجودة.

| الطبقة | التقنية |
| --- | --- |
| الواجهة | Next.js 16 (App Router · Turbopack) · React 19 · TypeScript · Tailwind 4 |
| البيانات | **SQLite دائم** عبر `node:sqlite` (مدمج في Node 22، بلا حزم أصلية): WAL + كتابة متزامنة داخل معاملة قبل كل استجابة. البيانات التجريبية اختيارية بـ `AM_DEMO_MODE=1` |
| المصادقة | جلسات HTTP-only (8 ساعات) + تحقق ثنائي بالبريد (6 أرقام، 5 دقائق، 5 محاولات) — الجلسات والتحديات في قاعدة البيانات فلا يُخرجك إعادة التشغيل، مع حد 8 محاولات دخول/15 دقيقة |
| الحسابات | أول تشغيل في الإنتاج ينشئ مديراً واحداً من متغيرات البيئة؛ كل حساب جديد يحصل على كلمة مرور مؤقتة عشوائية ويُلزم بتغييرها |
| الاختبارات | مؤقّت مرجعي على الخادم، حفظ فوري بمراجعة (revision)، تصحيح آلي للموضوعي، قرار حوادث بشري |
| الحضور | رمز QR متغيّر كل 20 ثانية، جهاز مسجّل، نطاق جغرافي 120 م، تجاوز معلم مسجّل |
| البحث | ⌘K في كل بوابة يبحث في الطلاب/المعلمين/المقررات/الاختبارات/الشكاوى حسب صلاحية الدور، وصفحة بحث داخل تطبيق الطالب |
| السجلات | إضافة طالب أو عضو هيئة تدريس من الواجهة أو عبر `POST /api/v1/students|teachers` — يُنشأ حساب دخول فعلي ويُكتب في التدقيق |
| التحقق | رمز QR على الهوية الرقمية يفتح صفحة تحقق عامة تعرض الحالة فقط (بلا درجات أو بيانات تواصل) |

## التشغيل

المستودع كامل **حزمة واحدة** في الجذر — `npm install` ثم `npm run dev`، بلا مساحات عمل ولا مجلدات فرعية:

```bash
npm install          # يثبّت كل الاعتماديات من الجذر
npm run dev          # http://localhost:3000  (يستمع على 0.0.0.0 للعرض داخل حاويات/معاينات)
npm run build        # بناء الإنتاج
npm run start        # تشغيل الإنتاج
npm run typecheck    # فحص الأنواع
npm run smoke        # اختبار E2E شامل (42 فحصاً) — يحتاج خادماً يعمل على :3000
npm run backup       # نسخة احتياطية متسقة من قاعدة SQLite
```

المتطلبات: **Node ≥ 20.9** و npm ≥ 10 (مثبّتة في `.nvmrc` و`.node-version` بالقيمة `22`). لا توجد أي اعتمادية أصلية (native) مطلوبة للتشغيل؛ أدوات توليد شعارات العلامة التجارية وحدها تحتاج حزمتين اختياريتين:

```bash
npm i -D @resvg/resvg-js fontkit     # فقط لإعادة توليد brand/*.png
```

> **ملاحظة للبناء في بيئات مختلفة:** ملف `package-lock.json` يولَّد شاملاً كل منصات بناء Next (linux-x64/arm64, darwin-x64/arm64, win32) حتى لا يفشل البناء على خادم بمعمارية مختلفة بسبب غياب حزمة `@next/swc` الأصلية. ملف الإعداد `next.config.mjs` مكتوب بـ JavaScript لا TypeScript، ليقرأه أي مُشغّل بلا تحويل مسبق.

### التشغيل على منصات الاستضافة الآلية (Google AI Studio / StackBlitz / CodeSandbox)

هذا التطبيق **Next.js بخادم Node** (Server Actions، Proxy، تصيير على الخادم) وليس تطبيق Vite ثابتاً.

- البنية الآن **حزمة واحدة في جذر المستودع**: `package.json` + `package-lock.json` + `app/` — بلا npm workspaces وبلا مجلد `web/`. هذا هو الشكل الذي تتوقعه منصات الاستيراد الآلي، وهو ما كان يسبب «Dependency installation failed» حين كان التطبيق داخل مجلد فرعي.
- كل اعتماديات البناء موجودة في `dependencies` (لا شيء حرج في `devDependencies`) حتى تعمل المنصات التي تثبّت بـ `--omit=dev`.
- أي منصة تشغّل `npm run dev` على Node ≥ 20.9 ستعمل مباشرة؛ الخادم يستمع على `0.0.0.0:3000`.
- منصة تقبل **Vite فقط** لن تشغّل هذا المشروع كما هو — استخدم معاينة Node (هذه البيئة) أو Vercel/أي مستضيف Node.

## النشر الإنتاجي

النسخة الإنتاجية تعمل بلا بيانات تجريبية: قاعدة بيانات SQLite دائمة، حساب مدير من متغيرات البيئة، تحقق ثنائي بالبريد، واستعادة كلمة مرور.

```bash
cp .env.example .env      # املأ AM_ADMIN_EMAIL · AM_ADMIN_PASSWORD · AM_BASE_URL · AM_SMTP_*
docker compose up -d --build
curl -fsS localhost:3000/api/health
```

- دليل التشغيل الكامل (Gmail، النسخ الاحتياطي، الصيانة، الحدود المعروفة): [`docs/13-production.md`](docs/13-production.md).
- **بلا بيانات تجريبية**: أي نشر بلا `AM_ADMIN_*` يتوقف برسالة واضحة بدل أن يخترع حسابات. للتجربة/التدريب فقط: `AM_DEMO_MODE=1`.
- **للتجربة السريعة هنا**: البيئة الحالية مضبوطة على `AM_DEMO_MODE=1` (حسابات العرض أدناه).

## تطبيق أندرويد (APK)

يوجد غلاف أصلي جاهز في `android/` + سير عمل يبني ملف APK على GitHub Actions:

- **Actions → Android APK → Run workflow** (اكتب عنوان الخادم) → نزّل `al-mohandes-debug-apk`.
- الـ APK غلاف WebView لكامل المنصة: أيقونة، كوكيز طرف أول، موقع جغرافي للحضور، رفع/تنزيل ملفات، وزر رجوع أصلي.
- عنوان الخادم قابل للتغيير من داخل التطبيق، فيعمل نفس الملف على أي نشر.

التفاصيل والقيود: [`docs/12-android-apk.md`](docs/12-android-apk.md).

## الحسابات التجريبية (وضع العرض فقط)

> تعمل هذه الحسابات فقط عندما يكون `AM_DEMO_MODE=1`. في الإنتاج لا توجد حسابات مسبقة إطلاقاً.

| الدور | البريد | كلمة المرور | يفتح |
| --- | --- | --- | --- |
| طالب | `student@almohandes.edu` | `Student@123` | تطبيق الطالب (جوال) |
| معلم | `teacher@almohandes.edu` | `Teacher@123` | لوحة المعلم |
| مراقب اختبارات | `supervisor@almohandes.edu` | `Super@123` | مركز المراقبة |
| مدير مؤسسة | `admin@almohandes.edu` | `Admin@123` | لوحة الإدارة |
| مدير منصة | `root@almohandes.edu` | `Root@123` | مركز التحكم |

> **إن ظهرت رسالة «انتهت صلاحية التحقق»:** افتح المعاينة في **تبويب مستقل** (لا داخل إطار)، ثم حدّث الصفحة تحديثاً كاملاً (Ctrl/Cmd+Shift+R) وسجّل الدخول. بعض المتصفحات تحجب كوكيز الطرف الثالث داخل الإطارات، فتضيع الجلسة بعد التحقق — وفي هذه الحالة تعرض المنصة صفحة `/welcome` تشرح السبب بدل إعادة توجيه صامتة.

مسارات مساعدة للتجربة (تُرجع 404 إلا عند `ALLOW_DEV_SESSION=1` أو في التطوير): `POST /api/dev/session` (جلسة ببريد)، `POST /api/dev/challenge` (رمز), `POST /api/dev/reset` (`{"examId","studentId"}` لتصفير محاولة، أو `{"reseed":true}` لإعادة كل البيانات التجريبية).

رمز التحقق يُعرض داخل شاشة التحقق في وضع العرض؛ في الإنتاج يُرسل بالبريد (Gmail/SMTP) ولا يُخزَّن إلا مُجزّأً (hash).

كل طالب ومعلم في البيانات التجريبية له حساب عامل أيضاً — بريد الطالب هو رقمه الجامعي بحروف صغيرة (`am20231002@almohandes.edu`) وكلمة المرور `Student@123`، وبريد المعلم مأخوذ من اسمه مع `Teacher@123`. بذلك يمكن فتح أي سجل في المنصة بشخصه الحقيقي، لا بحساب واحد فقط.

## الاختبار الآمن: ما نضمنه وما لا نضمنه

| القدرة | جهاز مُدار (MDM) | جهاز شخصي |
| --- | --- | --- |
| قفل التطبيقات الأخرى | نعم | لا |
| منع لقطات الشاشة | نعم (Android) / جزئياً (iOS) | لا |
| كشف تبديل التطبيق | نعم | نعم — حدث موثّق |
| كشف الجذر/كسر الحماية | نعم | نعم — يُسجَّل |
| منع تسجيل الشاشة | نعم | لا |

لا ندّعي حجزاً كاملاً للجهاز على الأجهزة الشخصية. المؤقّت من الخادم، الإجابات تُحفظ فوراً، وكل حادثة تُصنَّف وتُعرض على مراقب بشري — ولا تُلغى أي محاولة آلياً.
